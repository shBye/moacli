# UI 완성도 검토

검토일: 2026-09-08. 현재 스타일과 컴포넌트 구조를 바탕으로 한 제안이다.
이번 검토에서는 아래 시각 변경을 적용하지 않았다.

제품 기준: **최대한 사용자들이 사용하기 쉬우면서 편한 기능들을 제공하는 것**.
작은 시각적 차이로 현재 위치와 다음 동작을 더 쉽게 파악하게 하는 것이 우선이다.

| 우선순위 | 검토한 부분 | 개선 제안 | 사용성 효과 |
| --- | --- | --- | --- |
| 1 | 선택된 세션 탭 | 얕은 하단 그림자와 아주 약한 상단 내부 하이라이트를 더한다. 기존 강조색 밑줄은 유지한다. | 현재 작업 탭을 더 빨리 찾는다. |
| 2 | 탭의 상태와 조작 버튼 | 현재 hover·선택 상태에서는 알림 배지가 사라지고 조작 버튼이 나타난다. 승인·질문 대기 상태가 계속 식별되는 배치를 검토한다. | 탭에 마우스를 올려도 왜 주의가 필요한지 놓치지 않는다. |
| 3 | 주의 필요 탭 | 현재 테두리가 무한 반복된다. 정적인 상태 표시와 짧은 최초 강조를 비교한다. | 장시간 작업 중 시각적 피로를 줄인다. |
| 4 | 그림자·구분선 | 탭, 팝오버, 모달의 깊이를 공통 토큰으로 정리한다. 탭은 얕게, 열린 메뉴·모달은 더 분명하게 구분한다. | 겹친 화면의 관계를 쉽게 이해한다. |
| 5 | 탭 제목과 작은 버튼 | 현재 제목은 11px, 탭 조작 버튼은 19×23px이다. 제목 가독성과 클릭 영역을 유지하면서 밀도를 조정한다. | 고해상도 화면에서 읽고 누르기 쉬워진다. |
| 6 | 시작 버튼의 강조 | 현재 강조색 그림자가 넓게 퍼진다. 밝기와 번짐을 조금 줄인 버전을 비교한다. | 주변 입력 항목과의 균형을 맞춘다. |

## 탭 그림자 적용 시 확인할 점

관련 선택자는 src/styles.css의 `.session-tabs`, `.session-tab.active`,
`.session-tab.dragging`, `.session-tab.drop-before`, `.session-tab.drop-after`이다.

탭 스트립은 높이 42px, 탭은 31px이고 세로 overflow가 숨겨져 있다.
큰 그림자는 잘릴 수 있으므로 얕은 그림자와 내부 하이라이트부터 비교하는 것이 적절하다.
드래그와 드롭 위치 표시도 box-shadow를 사용하므로 상태별 우선순위를 함께 확인해야 한다.

선택된 탭과 hover 탭의 차이는 색·테두리·깊이로 명확히 유지한다.
키보드 포커스 표시는 그림자에 묻히지 않도록 별도로 검증한다.
반복되는 모션을 줄일 때 기존 reduced-motion 설정을 유지하고 공통 모션 토큰을 사용한다.

## 적용 전 비교 기준

- 탭이 1개·여러 개·가로 스크롤 상태일 때 선택된 탭이 바로 구분되는가?
- 승인·질문·실패 상태를 색뿐 아니라 아이콘·문구로도 구별할 수 있는가?
- hover, 키보드 포커스, 드래그 상태가 서로 충돌하지 않는가?
- 밝은 테마·어두운 테마·서로 다른 강조색에서 과도하게 번지거나 흐려지지 않는가?
- 터미널 출력·타이핑·IME 처리에는 변형이나 연속적인 그림자 애니메이션을 적용하지 않았는가?

첫 시각 개선 범위로는 **선택 탭의 얕은 그림자·내부 하이라이트와 구분선 정리**가 적절하다.
알림 배지의 표시 동작처럼 상태 처리에 영향을 주는 변경은 핵심 로직 협업 원칙에 따라
사용자와 동작을 합의한 뒤 구현한다.
