# Agent tasks — 진행 방향과 결정 기록

기능 변경 시 이 문서에 방향, 선택 이유, 구현 범위와 남은 과제를 함께 갱신한다.

## 2026-09-15: 메인이 책임지고 필요한 일만 한 단계 위임

사용자 합의 방향: 메인 CLI가 기본 담당자다. 필요하다고 판단한 작은 업무만 미니 에이전트에 위임한다. 미니는 재위임하지 않고 결과 또는 추가로 필요한 일을 메인에 돌려준다. 메인이 결과 통합과 최종 검증을 책임진다.

## 결정과 이유

- **깊이 1단계:** 재귀 위임의 비용 증가, 책임 분산과 중복 작업을 줄인다.
- **역할과 실행 모드 분리:** 역할은 지시 프리셋이다. 역할 이름이 수정 권한을 주지는 않는다.
- **기본 analyze, 명시적 edit:** 호출 CLI가 업무를 선택한다. 수정은 기본 수동 승인이고, 2026-09-16부터 별도 수정 자동 승인 옵션을 제공한다. 수정 자동 재시도는 하지 않는다.
- **최대 실행 3개, 열린 작업 10개:** 병렬 실행을 지원하면서 프로세스·계정 사용량 폭주를 제한한다. 승인된 초과 작업은 대기한다.
- **겹치는 폴더의 미니 수정 작업 직렬화:** 초기 단계에서 worktree 생성과 병합 흐름을 추가하지 않고 미니 작업 간 수정 충돌을 줄인다. 독립 폴더의 수정과 분석은 병렬 가능하다.
- **좁은 입력, 짧은 출력:** 전체 대화를 복제하지 않는다. 기본 결과 6,000자, 필요한 추가 결과만 페이지로 조회하며 로그는 요청할 때만 반환한다.
- **wait_task 최대 30초:** 모델의 잦은 상태 확인을 줄인다. 부모 모델을 자동 재개하는 push 방식은 아니다.
- **공통 레지스트리:** Tasks UI와 MCP가 승인·큐·취소·저장을 공유한다.

글자 제한은 토큰 예산 제한이 아니다. 실제 모델 입력·추론 비용을 강제 제한하지 않으며, 작은 일은 직접 처리하는 편이 저렴할 수 있다. 3/10 제한은 초기 정책값이다.

## 현재 구현

- 기본 역할: 코드 리뷰, 조사, 수정 계획, UI 피드백. MCP list_roles로 조회한다.
- start_task / delegate_task에 role과 mode를 지정한다. 역할 지시는 생성 시 프롬프트에 저장되어 이후 역할 변경과 분리된다.
- 비동기 흐름은 start_task → wait_task → get_task_result다. 작업별 ID로 여러 작업을 관리한다. check_task / cancel_task도 유지한다.
- 상태는 awaiting_approval → queued → running → 완료/실패/취소다. 승인 대기는 15분, 실행 시간 제한은 실제 시작부터 계산한다.
- 실행 중 취소는 프로세스 종료 확인까지 슬롯과 수정 폴더 예약을 유지한다.
- MCP 입력 폴더는 실제 경로로 정규화한다. 수정 모드는 폴더 지정이 필수다.
- 세션 Tasks 탭은 Git 변경 스냅샷 분석 진입점이다. UI에는 아직 직접 수정 모드가 없다. 선택한 결과로 수정 요청 초안을 만들어 원래 CLI에 Enter 없이 넣는다.
- 사용자 정의 역할 CRUD는 아직 미구현이다. 이후 데이터 기반 카탈로그를 확장하되 실행 엔진·권한 정책은 공유한다.

## 재위임 제한의 보장 범위

워커에 단일 단계 지시와 MOACLI_DELEGATED=1, 깊이 1 표시를 전달한다. 워커의 MoaCLI MCP 연결과 CLI 내장 하위 에이전트 기능을 비활성화한다. Claude Agent/Task 도구와 Codex multi-agent 기능을 차단한다. 레지스트리는 깊이 0 호출만 수락하며 MCP도 자식 깊이 입력/헤더를 거부한다.

Codex는 별도 임시 폴더에서 사용자 설정·규칙을 무시하고 실행한다. 수정 대상 폴더만 추가 쓰기 경로로 지정한다. 계정 인증은 유지하지만 사용자 모델/provider 설정과 달라질 수 있다. CLI 옵션은 로컬 도움말과 공식 문서로 확인했다. 지원하지 않는 버전에서는 실패하며 권한을 넓혀 재시도하지 않는다.

이는 정상적인 에이전트의 재위임 경로를 막는 정책이지, 악의적인 같은 사용자 프로세스를 격리하는 OS 보안 경계가 아니다. 일반 작업은 셸을 사용할 수 있으므로 다른 CLI를 직접 실행하거나 인증 정보를 찾아 호출하는 우회까지 절대적으로 차단하지는 못한다. 깊이 헤더도 인증된 실행 신원 자체는 아니다. 더 강한 보장은 별도 자격증명·프로세스/컨테이너 격리가 필요하다.

## 동시 수정의 한계

폴더 예약은 MoaCLI가 관리하는 미니 수정 작업 사이에만 적용된다. 원래 CLI, 외부 편집기 등의 쓰기는 막지 않는다. 메인은 미니가 수정 중인 파일을 함께 수정하지 않아야 한다. 분석도 실행 중 바뀌는 파일을 읽을 수 있다. 별도 worktree와 결과 병합 UI는 후속 과제다.

## 검증 및 다음 순서

스냅샷·프롬프트·결과 파싱 테스트와 가짜 워커 + 실제 임시 SQLite DB 기반 승인/큐/취소/깊이 제한 테스트를 추가했다. scripts/delegation-tasks.test.cjs는 Electron ABI의 SQLite를 사용하므로 ELECTRON_RUN_AS_NODE=1로 Electron에서 실행한다. 테스트에서는 유료 모델을 실행하지 않는다.

실제 계정의 분석/수정 왕복 실행과 UI 수동 QA는 별도 확인이 필요하다. 다음 순서는 작은 실제 작업으로 사용성 확인 → 입력 컨텍스트 선택 개선 → 사용자 역할 편집 → 필요 시 격리 작업공간이다.

현재 확인 결과: 스냅샷 테스트 7개, 위임 정책/큐 테스트 5개, 기존 회귀 테스트 37개 통과. 타입 검사와 프로덕션 빌드 통과. 실제 유료 CLI 실행은 하지 않았다.

## 2026-09-15: MCP 작업과 원래 세션 연결 — 자동 연결 구현

사용자는 실제 CLI 연동 확인을 완료했다고 알렸으며, 다음으로 MCP 위임 작업을 원래 세션의 Tasks에서 확인하는 기능을 요청했다. 앞의 유료 CLI 미실행 기록은 개발자 자동 검증 범위를 뜻한다.

기존 MCP 작업에는 호출한 세션 식별자가 없고, 스냅샷 작업에만 원본 세션 메타데이터가 있었다. 작업 폴더나 현재 선택한 탭으로 원본을 추정하면 동일 폴더의 여러 세션이 섞일 수 있으므로 사용하지 않는다.

권장안: 앱이 CLI를 시작할 때 세션별 연결 식별자를 MCP 연결 설정에 자동 전달하고, 서버가 작업 생성 시 원본 세션을 저장한다. 원본 대화의 영구 history ID가 확인되면 연결을 보강하여 다시 열었을 때도 조회한다. 식별자 없는 외부 MCP 호출은 전역 작업 목록에 유지한다. 기존 실행 세션에는 재시작이 필요할 수 있다.

대안: 호출 CLI가 작업 도구 인자로 세션 ID를 직접 전달한다. 연결 설정 변경은 적지만 모델의 ID 조회/전달 비용과 누락 가능성이 있다.

사용자가 자동 연결을 선택하여 구현했다. 모델이 세션 ID를 조회하거나 인자로 전달할 필요가 없어 추가 모델 토큰이 들지 않는다.

### 구현 범위와 이유

- MoaCLI에서 시작하는 Claude/Codex의 moacli MCP 연결에 실행별 토큰을 주입한다. 전역 설정 파일을 수정하지 않고 다른 MCP 서버는 유지한다. 로그인용 세션 및 다른 CLI 프로필은 자동 주입 대상이 아니다.
- 메인 프로세스가 PTY와 연결 토큰의 매핑을 소유한다. 종료·시작 실패·호스트 크래시·앱 종료 시 폐기하고, 전역 토큰 재생성 시에도 폐기한다. 토큰은 작업 DB에 저장하지 않는다.
- MCP 인증에서 확인한 원본을 source_json으로 저장한다. 도구 프롬프트나 작업 폴더에서 원본을 추측하지 않는다. 재시도는 원본 연결을 유지한다.
- 새 대화의 historyKey가 뒤늦게 확인되어도 Tasks 탭이 닫힌 상태에서 연결을 보강한다. 네이티브 기록이 생기지 않은 대화는 앱 재시작 후 자동 복원할 수 없다.
- Tasks 상단에서 해당 CLI의 최근 30개 MCP 작업 상태·요청·결과를 볼 수 있다. 기존 승인 창을 열거나 작업을 취소하고 결과를 복사할 수 있다. 스냅샷 분석 UI는 별도로 유지한다.
- 작업 완료 알림은 열려 있는 원래 세션의 Tasks로 이동한다. 닫힌 원본 세션은 자동 실행하지 않고 기존 전역 목록으로 이동한다.
- 외부 터미널의 기존 공유 토큰 호출과 과거의 원본 없는 작업은 전역 목록에 남긴다. 소급하여 임의 연결하지 않는다.
- 기존 CLI 세션은 재시작해야 자동 연결된다. 서버가 꺼진 상태에서 시작한 세션도 활성화 후 재시작이 필요하다. 토큰을 재생성한 경우 열린 CLI도 재시작한다.

이 매핑은 같은 사용자 로컬 앱의 세션 구분을 위한 것이다. OS 수준 프로세스 격리나 서로 다른 사용자 사이의 작업 접근 제어를 추가한 것은 아니다. CLI 관리 정책이 MCP를 금지하면 이를 우회하지 않는다.

OpenAI Docs를 사용하여 실행별 HTTP MCP 설정을 확인했다: [Codex MCP](https://learn.chatgpt.com/docs/extend/mcp?surface=cli). Claude 실행 설정은 [Claude MCP](https://code.claude.com/docs/en/mcp)를 참조했다.

검증: 실제 로컬 HTTP MCP 요청의 세션 귀속/외부 호출 분리/폐기 토큰 거부, SQLite 원본 저장·재시도·대화 재오픈 복원, 같은 폴더의 세션 분리, 설치된 Codex의 설정 파싱을 모델 호출 없이 확인했다. 자동 연결을 포함한 실제 유료 대화와 UI 수동 클릭 검증은 이번 검증에 포함하지 않았다.

최종 확인: 위임/자동 연결 테스트 10개 + 기존 테스트 44개 = 54개 통과. PTY 시작 실패·정상 종료 시 토큰 해제도 포함한다. 타입 검사 및 프로덕션 빌드 통과.

## 2026-09-16: Tasks 조회·렌더링 최적화와 붙여넣기 보완

사용자가 검토에서 제안한 네 가지 보완을 승인하여 적용했다. 터미널 엔진 교체나 무분별한 memo 추가 대신 확인된 불필요한 데이터 이동·렌더링을 줄인다.

1. 터미널 memo 비교에 pendingPaste의 ID와 내용을 포함했다. 다른 표시 속성이 그대로여도 새 붙여넣기 요청이 무시되지 않게 한다. 같은 요청의 중복 삽입 방지는 유지한다.
2. syncTaskSource IPC로 원본 연결 갱신을 분리했다. 연결을 보강하려고 리뷰·작업 전체 결과를 조회하지 않는다. 목록 API는 읽기 전용이며, 단순 실행 상태 변경은 연결 재동기화 조건에서 제외한다. 전송 전에 요청 식별자를 기록해 같은 요청이 진행 중일 때 중복 전송하지 않는다.
3. 현재 세션과 작업 종류별 변경 식별자를 사용한다. 다른 세션의 작업이나 서버 설정만 바뀌면 현재 MCP/스냅샷 목록을 재조회하지 않는다.
4. MCP 목록은 제한된 프롬프트·결과 미리보기만 반환한다. DB 목록 쿼리에서도 전체 본문을 읽지 않는다. 결과를 펼쳐야 별도 IPC로 본문을 조회하고 Markdown을 생성한다. 접으면 Markdown을 해제하며, 같은 화면에서 다시 펼칠 때 이미 받은 본문을 재사용한다. 실패 시 다시 불러오기 버튼을 제공한다.

검증: 자동 테스트 60개 통과. 새 테스트는 붙여넣기 변경 감지/중복 소비 방지, 진행 중 연결 요청 중복 억제, 타 세션 변경 시 조회 생략, 접힌 결과의 조회·Markdown 생성 생략, 펼침/재펼침, 읽기 전용 목록과 별도 연결 갱신, 큰 결과의 요약 전송을 포함한다. 테스트 데이터에서 70만 자 결과와 5만 자 요청을 가진 작업도 목록 직렬화 크기는 6천 자 미만이고, 별도 결과 조회는 원문을 보존한다. 이는 기능 테스트이며 실제 CPU·메모리·프레임 성능 벤치마크는 아니다.

## 2026-09-16: 자동 승인 옵션 분리 및 설정 공통 UI

- 사용자 요청으로 분석 자동 승인과 파일 수정 자동 승인을 독립 설정으로 분리했다. 기존 autoApprove는 분석 설정으로 유지하고 autoApproveEdits는 기본 false로 읽는다. 기존 분석 자동 승인을 켠 사용자에게 수정 권한이 자동으로 추가되지 않는다.
- 새 요청에만 적용한다. 이미 대기 중인 작업을 소급 승인하지 않고, 재시도 및 스냅샷 작업은 공통 자동 승인 대상에서 제외한다. 수정 자동 재시도 금지는 유지한다. 동시 실행 제한과 폴더 수정 직렬화도 그대로다.
- 설정에서 파일 변경 경고를 표시한다. MCP 도구 설명도 사용자 승인 정책을 따르도록 갱신했다.
- 기존 공통 SelectBox를 재사용하고 스타일을 components/select-box.css로 분리했다. 설정용 variant로 계정·외관·위임 설정의 크기를 통일한다. 버튼과 portal 메뉴 글자 크기를 모두 명시해 전역 기본 글꼴 크기가 새어들지 않게 했다.
- SettingsDescription 공통 컴포넌트를 추가해 설명과 경고의 크기·줄간격을 관리한다. 외부 터미널 안내를 짧게 줄였다. 키보드 선택·포커스·disabled 동작은 기존 컴포넌트를 유지한다.
- 승인 정책의 네 가지 조합, 이전 설정 기본값 및 저장/복원 테스트를 추가했다. 직접 실행 UI는 기존 Preview changes → Start task를 유지하며, 변경사항 없는 범용 Run 화면은 이번 범위에 포함하지 않는다.

후속 사용성 보완: 실제 버튼 문구를 Preview Git changes → Run analysis로 변경했다. 세션 폴더 경로와 Git 저장소·초기 커밋·미커밋 변경사항 조건을 화면에 표시한다. 비 Git 폴더에서는 원시 git 명령 오류 대신 올바른 프로젝트 세션에서 다시 실행하라는 안내를 반환한다. 터미널 내부 cd를 추적하거나 자동 git init을 하지는 않는다. 비 Git 폴더 회귀 테스트 포함 총 63개 자동 테스트와 타입 검사·빌드를 확인한다. 실제 UI 시각 검증은 별도다.

## 2026-09-16: 알림 상세 정보와 데스크톱 미리보기

- 앱 내부 알림에 본문, CLI·역할·분석/수정 모드·프로젝트 폴더명, 종료된 위임 작업의 실행 소요 시간, 짧은 결과/오류 미리보기, 다음 행동 안내를 제공한다. 원본 세션이 있으면 제목으로 사용한다.
- 일반 CLI 이벤트는 실제로 수집한 도구명·오류 코드·프로세스 종료 코드만 표시한다. Codex OSC9는 계속 일반 attention으로 취급한다. 로그를 임의로 요약하거나 완료/성공을 추측하지 않는다.
