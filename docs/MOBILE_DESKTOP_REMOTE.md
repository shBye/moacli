# MoaCLI 모바일–Desktop 리모트 논의 메모

작성일: 2026-09-08. **통신 구조·인증 구조·운영 주체는 사용자와 함께 결정한다.**
이 문서는 확정 설계나 구현 지시가 아니다. 모바일 앱과 리모트 통신은 아직 구현하지 않았다.

## 협업 원칙

통신·인증·데이터 처리·저장·동기화·상태 관리 같은 핵심 로직은
설계안과 변경 범위를 사용자와 합의한 뒤 구현한다.
이 원칙은 리모트 기능뿐 아니라 프로젝트 전반에 적용한다.
미합의 상태에서는 조사·검토·문서화·검증까지만 진행한다.

## 확인된 제품 방향

- 모바일 앱이 실제 MoaCLI Desktop과 양방향으로 소통한다.
- 실행 중인 Claude·Codex 작업을 확인하고, 지원 가능한 경우 질문 응답·승인·후속 요청을 전달한다.
- CLI 실행과 로컬 파일 작업은 Desktop에서 이어가는 경험을 목표로 한다.
- Claude Remote Control과 유사하게 로컬 작업을 다른 기기에서 이어가는 방향이다.
  공식 Remote Control 프로토콜을 그대로 사용하거나 연동한다고 결정한 것은 아니다.

## 현재 구현 범위

현재 작업은 알림 이벤트의 분류와 Desktop 내부 전달을 개선했다.
상세 매핑, 버전 기준, 테스트, 제공자별 한계는 [AGENT_EVENTS.md](./AGENT_EVENTS.md)에 있다.

모바일·중계 서버·페어링·원격 승인 API는 만들지 않았다.
현재 HTTP Hooks는 관찰 후 빈 JSON을 반환하며 승인이나 거절을 수행하지 않는다.
현재 알림함은 임시 상태이고, 원격 명령 저장소나 승인 요청 원장이 아니다.

직접 연결·중계 서버·특정 인증 체계 중 어느 것도 선택된 상태가 아니다.
후속 설계에서 선택 이유와 비용·운영·사용성 영향을 함께 기록한다.

## 설계 시 해결해야 할 기술 문제

1. 알림 전달과 실제 명령 실행을 구분해야 한다. 모바일 전송 성공만으로 Desktop 적용 완료를 표시할 수 없다.
2. PC와 모바일이 같은 요청에 답하거나 네트워크 재시도로 명령이 중복돼도 중복 실행되지 않아야 한다.
3. 터미널 재시작 후 이전 실행의 승인 요청이 새 실행에 적용되지 않아야 한다.
4. 이미 처리됐거나 만료된 요청과 현재 유효한 요청을 구분해야 한다.
5. 알림 읽음·삭제와 실제 질문·승인 해결 상태를 구분해야 한다.
6. Codex OSC9에는 구조화된 요청 ID나 승인 결과가 없다. 추가 연동 없이 원격 승인 대상으로 사용할 수 없다.
7. 새로운 SDK나 App Server를 시작하는 것만으로 기존 PTY 세션에 연결된다고 가정하면 안 된다.
8. CLI에 단순히 y나 Enter를 보내는 방식은 화면이 바뀌면 다른 질문에 답할 수 있다.

위 문제의 구체적 해결 방식과 필드·프로토콜은 아직 정하지 않았다.

세부 구조를 구현하기 전에 사용자와 합의한 결정을 이 문서에 기록한다.
