# macOS 지원 검토

검토일: 2026-09-08. **계획 문서이며 macOS 지원은 아직 구현하지 않았다.**
현재 우선순위는 Windows 안정화와 UI 개선이다.

## 범위 판단

Electron·React·xterm 기반 UI와 기능 상당 부분을 재사용할 수 있는 중간 규모의 작업이다.
개발용 실행과 정식 배포를 구분해야 한다. 실제 mac에서 검증하기 전까지 작업 기간을 확정하지 않는다.

| 영역 | 현재 코드와 필요한 작업 |
| --- | --- |
| 기본 셸 | 기본 프로필과 여러 UI 정책이 powershell ID에 묶여 있다. OS별 셸과 기능 기준으로 분리하고 mac의 zsh 실행을 검증한다. |
| CLI 탐색 | 비 Windows에서는 PATH 탐색에 의존한다. Finder 실행 환경에서도 Homebrew·사용자별 설치의 Claude와 Codex를 찾는지 확인한다. |
| 터미널 | ConPTY/POSIX 분기는 이미 있다. Codex Shift+Enter의 Windows 전용 시퀀스는 플랫폼별 처리가 필요하다. |
| 입력·클립보드 | Cmd 단축키, 한글 IME, 이미지와 Finder 파일 복사, 셸 경로 인용을 검증한다. Windows IME 패치가 mac에 미치는 영향도 확인한다. |
| 프로세스·파일 | 비 Windows 작업 종료는 부모 PID만 종료한다. 자식 프로세스 정리와 중첩 대화 파일 변경 감지를 검토한다. |
| 계정·대화 | CLI 인증 저장 방식, 경로 대소문자, 계정 탐색을 mac에서 확인한다. 인증·데이터 처리 변경은 공동 설계 후 진행한다. |
| 창·알림 | mac 창 버튼, 메뉴, Cmd-Q와 창 닫기, 알림 권한과 포커스 동작을 점검한다. |
| 빌드 | 현재 Windows NSIS만 설정되어 있다. mac 설치 파일·아이콘과 node-pty/better-sqlite3의 아키텍처별 빌드를 준비한다. |
| 업데이트 | 현재 MoaCLI-Setup.exe만 선택한다. OS·아키텍처별 배포 파일 선택이 필요하다. |

## 권장 진행 순서

1. Windows의 터미널 안정성을 확보한다.
2. OS 의존 부분의 분리 범위를 사용자와 합의한다.
3. mac 개발 빌드에서 CLI 시작·첫 질문·승인·완료 알림·세션 복원을 검증한다.
4. 한글 입력, 연속 출력, 탭 이동, 리사이즈, 종료 후 잔여 프로세스를 실제 mac에서 확인한다.
5. 서명·공증·설치·업데이트를 검증한 뒤 정식 지원으로 안내한다.

일반 사용자 배포에는 코드 서명과 Apple 공증을 준비한다. macOS 빌드 환경과 인증서가 필요하다.
참고: [Electron 코드 서명 및 macOS 공증 안내](https://www.electronjs.org/docs/latest/tutorial/code-signing).

## 함께 결정할 사항

- Apple Silicon 우선 지원 여부와 Intel 지원 범위, 최소 macOS 버전.
- 실기기 테스트 환경과 mac 빌드 CI의 운영 주체.
- 서명 계정·인증서 관리와 릴리즈 운영 방식.
- OS별 셸·프로세스·업데이트 어댑터의 책임 범위.

리모트는 Windows와 mac 데스크톱 모두를 연결 대상으로 고려한다.
통신·인증·데이터 처리·운영 주체는 기존 원칙대로 사용자와 공동 설계하며,
이 문서가 해당 구조를 확정하거나 구현을 승인하는 것은 아니다.
